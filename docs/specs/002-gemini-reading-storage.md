# 002 Gemini 사주 해석과 결과 저장

## 상태

- 문서 작성 완료
- Gemini 해석 구현 및 검증 완료
- localStorage 저장 정책 결정과 구현은 보류
- 2026-09-23: 참가자의 새 요청으로 저장 방식을 Google 계정별 데이터베이스로 변경했습니다. 저장 요구사항은 `003-google-sign-in.md`, `004-saved-readings.md`가 우선합니다. 이 문서의 localStorage 절은 이전 계획으로 남깁니다.

## 목적

기존 샘플 규칙 답변을 Gemini 기반 맞춤 사주 해석으로 교체하고, 생성된 결과를 같은 브라우저에서 다시 볼 수 있도록 `localStorage`에 저장합니다.

## 사용자 가치

- 계산된 사주와 현재 상황이 함께 반영된 해석을 받습니다.
- 새로고침하거나 브라우저를 다시 열어도 저장된 결과를 다시 확인할 수 있습니다.
- AI 호출이 실패했을 때 샘플 답변을 실제 결과처럼 보여주지 않고 실패 여부를 분명히 알 수 있습니다.

## 확정된 기술 결정

- 모델 ID: `gemini-3.5-flash-lite`
- 공식 모델 문서: https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite
- API 키 환경변수: `GEMINI_API_KEY`
- API 키는 서버에서만 읽고 브라우저 코드, 응답, 로그, Git에 포함하지 않습니다.
- 사주 계산은 기존 `lib/saju`가 담당하며 Gemini에게 다시 계산시키지 않습니다.
- Gemini에는 생년월일과 출생시간 원문을 보내지 않습니다.
- Gemini에는 계산된 사주 결과, 현재 상황, 질문과 필요한 이전 대화만 전달합니다.
- 결과 저장 위치: 사용자의 브라우저 `localStorage`
- 서버 데이터베이스 저장은 이번 범위에 포함하지 않습니다.

## 핵심 흐름

1. 사용자가 출생 정보와 현재 상황을 입력합니다.
2. 기존 계산 기능이 브라우저에서 사주 원국을 계산합니다.
3. 브라우저가 계산 결과, 현재 상황, 질문을 서버 API에 전송합니다.
4. 서버 API가 입력 형식과 길이를 검사합니다.
5. 서버가 `gemini-3.5-flash-lite`에 해석을 요청합니다.
6. 서버가 Gemini 응답의 구조와 필수 항목을 검사합니다.
7. 브라우저가 쉬운 요약 카드와 자세한 근거를 표시합니다.
8. 검증된 결과를 `localStorage`에 저장합니다.
9. 후속 질문은 최대 3회까지 같은 상담 맥락을 포함해 요청합니다.
10. 새로고침 시 유효한 저장 결과가 있으면 화면을 복원합니다.

## Gemini 입력

### 포함

- 년주·월주·일주·시주
- 일간과 대표 오행 집계
- 계산 방식과 한계 설명
- 현재 직업 상태
- 가장 큰 고민
- 원하는 변화 시점
- 사용자가 작성한 현재 상황과 질문
- 후속 질문 시 이전 질문·답변 중 필요한 대화

### 제외

- Gemini API 키
- 생년월일 원문
- 출생시간 원문
- 이메일, 이름, 연락처 등 서비스에 필요하지 않은 개인정보
- 브라우저의 다른 저장 데이터

## Gemini 출력 형식

Gemini 응답은 자유 문장 그대로 사용하지 않고, 다음 구조의 JSON으로 받습니다.

```ts
type GeminiReading = {
  version: 1;
  cards: Array<{
    id: "career" | "core" | "timing";
    title: string;
    summary: string;
    evidence: string;
    action: string;
  }>;
  conclusion: string;
  realityChecks: string[];
  disclaimer: string;
};
```

### 출력 규칙

- 카드는 `career`, `core`, `timing` 세 개를 각각 한 번씩 포함합니다.
- 결론은 분명하게 제안하되 미래·취업·수익을 보장하지 않습니다.
- 각 카드에는 계산 결과의 근거와 현실에서 확인할 다음 행동이 있습니다.
- 사용자의 현재 상황을 구체적으로 반영합니다.
- 전문 용어에는 쉬운 설명을 붙입니다.
- 입력에 없는 사실을 실제 경험처럼 지어내지 않습니다.
- 재정 질문에는 손실 가능성과 현실에서 확인할 조건을 포함합니다.

## 서버 API 동작

- 예상 경로: `POST /api/readings`
- 요청 본문은 허용된 필드만 받습니다.
- 문자열 길이와 후속 질문 횟수를 서버에서도 검사합니다.
- API 키가 없으면 Gemini를 호출하지 않고 설정 오류를 반환합니다.
- Gemini 응답이 JSON 규칙을 만족하지 않으면 저장하지 않고 형식 오류를 반환합니다.
- 요청 실패, 사용량 제한, 시간 초과는 서로 구분 가능한 오류로 반환합니다.
- 오류가 발생했을 때 샘플 답변을 실제 Gemini 결과로 바꾸어 보여주지 않습니다.

## localStorage 동작

- 저장 키에는 서비스 이름과 버전을 포함합니다. 예: `saju-career:reading:v1`.
- JSON을 읽을 때 버전과 필수 필드를 검사합니다.
- 깨졌거나 예상하지 못한 데이터는 사용하지 않고 안전하게 초기화합니다.
- 서버에서 검증된 Gemini 결과만 저장합니다.
- API 키와 서버 오류 원문은 저장하지 않습니다.
- 저장 실패 시 화면 결과는 유지하되 “이 기기에 저장하지 못했습니다”라고 안내합니다.

### 구현 전에 정할 항목 (TBD)

1. 저장 필드: 계산 결과·Gemini 해석·저장 시각 외에 현재 상황과 후속 대화를 포함할지
2. 저장 개수: 가장 최근 결과 1개 또는 여러 결과의 기록 목록
3. 보관 기간: 자동 만료 여부
4. 삭제 기능: 자동 교체, `결과 삭제` 버튼, 전체 기록 삭제 중 어떤 방식을 제공할지
5. 공용 기기 안내 문구와 사용자가 저장을 끌 수 있는 선택권

## 개인정보와 보안

- `localStorage`는 암호화된 비밀 금고가 아니며 같은 브라우저를 사용하는 사람이 볼 수 있습니다.
- 민감한 현재 고민과 대화를 저장하기 전 사용자에게 저장 범위를 안내해야 합니다.
- 사용자 입력을 명령으로 실행하지 않고 해석 자료로만 취급합니다.
- 서버 로그에 API 키와 전체 사용자 입력을 남기지 않습니다.
- 화면에는 “사주 해석은 참고 자료이며 중요한 직업·재정 결정은 현실 조건을 함께 확인해야 한다”는 안내를 표시합니다.

## 로딩과 오류 화면

- 요청 중에는 버튼을 비활성화하고 진행 중임을 표시합니다.
- 중복 제출을 막습니다.
- API 키 없음: “Gemini 연결 설정이 필요합니다.”
- 사용량 제한: “요청이 많아 잠시 후 다시 시도해주세요.”
- 시간 초과 또는 네트워크 오류: “연결하지 못했습니다. 다시 시도해주세요.”
- 응답 형식 오류: “해석 결과를 확인하지 못했습니다. 다시 요청해주세요.”
- 오류 화면에 API 키, 내부 응답 전문, 프로그램 경로를 노출하지 않습니다.

## 완료 조건

- 정상 입력 시 `gemini-3.5-flash-lite`가 만든 카드 3개가 표시됩니다.
- 요청에 생년월일·출생시간 원문이 포함되지 않습니다.
- 응답 형식 검사를 통과한 결과만 화면 표시와 저장에 사용됩니다.
- 새로고침 후 저장된 결과를 복원할 수 있습니다.
- 후속 질문은 최대 3회이며 앞선 상담과 모순되지 않는 맥락을 전달합니다.
- API 키 없음, 사용량 제한, 네트워크 오류, 형식 오류가 각각 안전한 사용자 문장으로 표시됩니다.
- 실제 결과와 샘플 결과가 화면에서 명확하게 구분됩니다.
- 관련 타입 검사, 자동 Test, Eval과 브라우저 확인을 모두 통과합니다.

## Eval 기준

1. 사주 요소와 현재 상황이 답변에 구체적으로 반영됩니다.
2. 서로 다른 사주·상황 입력의 핵심 근거와 제안이 구별됩니다.
3. 결론은 분명하지만 미래와 수익을 확정하지 않습니다.
4. 계산값과 해석이 서로 모순되지 않습니다.
5. 현실에서 확인할 조건과 다음 행동이 포함됩니다.
6. 샘플 결과와 실제 Gemini 결과를 사용자가 혼동하지 않습니다.

## 검증 결과

- `POST /api/readings`에서 `gemini-3.5-flash-lite`를 실제 호출합니다.
- 카드 3개와 결론·현실 확인 조건을 화면에 표시하고, 후속 질문을 최대 3회까지 처리합니다.
- API 키는 서버 환경변수에서만 읽으며, Gemini 요청에는 생년월일·출생시간 원문을 포함하지 않습니다.
- 독립 테스트에서 타입 검사와 전체 Test 31개가 통과했습니다.
- 브라우저에서 실제 Gemini 해석과 후속 질문 1회를 확인했고 콘솔 오류가 없었습니다.
- localStorage 저장·복원은 정책 확정 전이므로 아직 구현하지 않았습니다. 따라서 이 Spec은 완료 상태로 표시하지 않습니다.
