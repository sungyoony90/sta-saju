# 004 사주 해석 결과 데이터베이스 저장

## 상태

- 작성일: 2026-09-23
- 구현 및 단일 계정 저장·복원 검증 완료

## 목적

Google로 로그인한 사용자가 Gemini의 검증된 사주 해석을 자신의 계정에 저장하고, 나중에 다시 열어볼 수 있게 합니다.

## 저장 범위

- 계산된 사주 원국, 검증된 Gemini 해석 카드·결론·현실 확인 조건, 모델 이름, 생성 시각, 소유자 ID를 저장합니다.
- 생년월일·출생시간 원문, Gemini API 키, Google 토큰, 이메일 주소는 저장하지 않습니다.
- 이번 구현에서는 현재 상황·질문 원문과 후속 대화를 저장하지 않습니다. 과거 결과를 연 뒤 후속 상담을 이어갈 수 없다고 안내합니다. 사용하면서 조정할 수 있습니다.
- 여러 결과를 저장하고 최근 결과 10개를 화면에 보여줍니다. 사용자가 자신의 결과를 삭제할 수 있습니다.

## 데이터베이스

- Supabase `public.saju_readings` 테이블을 사용합니다.
- 각 행은 `id`, `user_id`, `created_at`, `chart`, `reading`, `model`을 가집니다.
- `user_id`는 `auth.users.id`를 참조합니다. 계정이 삭제되면 연결된 기록도 정리됩니다.
- 행 수준 보안(RLS)을 켜고 인증 사용자의 `auth.uid() = user_id`인 행에만 조회·추가·삭제를 허용합니다.
- 익명 사용자는 해당 테이블을 읽거나 쓰지 못합니다.
- 서비스 역할 비밀키를 앱에 추가하지 않습니다.

## 사용자 흐름

1. 사용자가 사주와 고민을 입력하고 Gemini 해석을 받습니다.
2. Gemini 응답 구조 검사를 통과한 결과만 저장 대상으로 삼습니다.
3. 로그인 상태라면 사용자 ID와 필요한 결과 필드만 데이터베이스에 추가합니다.
4. 저장 성공·실패 상태를 해석 화면에 분명히 표시합니다. 저장 실패해도 생성된 해석은 화면에 남습니다.
5. 로그인 사용자는 최근 결과를 열고 자신의 기록을 삭제할 수 있습니다.
6. 로그아웃하면 저장 목록과 현재 화면의 개인 결과를 지웁니다.

## 오류와 개인정보

- 저장된 JSON을 화면에 표시하기 전 구조를 검사합니다. 깨진 결과는 건너뛰고 오류를 안내합니다.
- 다른 사용자 ID를 요청 본문에 넣더라도 RLS가 저장·조회·삭제를 거절해야 합니다.
- 저장 전 사용자에게 계정에 보관되는 항목을 안내합니다.
- 무제한 보관은 추후 정책을 정할 때 조정합니다. MVP에는 본인 삭제 기능을 둡니다.

## 완료 조건

- 로그인 사용자의 정상 Gemini 결과가 데이터베이스에 저장됩니다.
- 새로고침 또는 재로그인 후 자신의 결과를 다시 볼 수 있습니다.
- 익명 사용자는 저장 데이터를 읽거나 쓰지 못합니다.
- 다른 계정의 결과는 볼 수 없고 삭제할 수 없습니다.
- 생성 실패나 저장 실패를 성공으로 표시하지 않습니다.
- 타입 검사, 관련 자동 테스트, RLS 검증, 브라우저 확인이 통과합니다.

## 검증 결과

- Supabase SQL 편집기에서 테이블·인덱스·RLS 정책 적용이 성공했고, 테이블과 세 정책(조회·추가·삭제)을 관리 화면에서 확인했습니다.
- 익명 사용자의 데이터 API 조회는 HTTP 401로 거절됐습니다.
- 실제 Google 로그인 계정에서 테스트용 Gemini 해석을 저장하고, 새로고침 후 다시 열어 세 카드와 결론을 복원했습니다.
- 참가자 승인 후 테스트 기록 1개를 삭제했고, 새로고침 후에도 목록에 남지 않는 것을 확인했습니다.
- 타입 검사, 자동 테스트 36개, 배포용 빌드가 통과했습니다.
- 별도 두 번째 계정으로 타인 기록 조회·삭제를 직접 시도하지는 않았습니다. 본인 ID 비교 정책을 확인한 상태입니다.
