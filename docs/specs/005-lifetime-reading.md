# 005 — 내 사주 전체 풀이

상태: 구현 및 검증 완료

## 목적

사용자가 취업 상태나 현재 고민을 입력하지 않아도 출생 원국을 바탕으로 삶 전반에서 반복될 수 있는 경향을 이해하게 합니다. 풀이를 확정된 미래처럼 제시하지 않고, 계산값과 연결된 설명 및 현실에서 스스로 점검할 질문을 함께 제공합니다.

## 사용자 가치

- 출생 정보 한 번으로 성향·강점·관계·일·돈의 기본 경향을 한눈에 봅니다.
- 어려운 사주 용어를 몰라도 쉬운 요약을 먼저 읽을 수 있습니다.
- 해석에 사용된 계산 근거를 확인하고 맹신하지 않을 수 있습니다.
- `앞으로의 흐름`으로 이동해도 같은 출생 원국을 다시 입력하지 않습니다.

## 범위

### 포함

- 현재 계산기가 지원하는 양력 생년월일과 정확한 출생시간 입력
- `lib/saju`가 계산한 년주·월주·일주·시주, 일간, 대표 오행 집계 사용
- `내 사주 전체` 메뉴와 전체 풀이 생성·재시도 화면
- 한 줄 요약과 성향·강점·관계·일·돈 카드
- 카드별 쉬운 설명, 계산 근거, 현실 점검 질문
- 로그인 사용자의 검증된 결과 저장을 위한 새 풀이 종류 구분
- 기존 취업 풀이 기록과의 하위 호환

### 제외

- 현재 고민, 취업 상태, 질문을 받아 해결책을 제시하는 상담
- 특정 사건의 발생 시점, 수명, 질병, 합격, 취업 또는 수익의 단정
- 올해 또는 미래 연도 흐름(006 Spec)
- 오행·용어 및 카드 근거 UI의 상세 동작(007 Spec)
- 궁합, 타인 사주, 음력 입력, 출생시간 미상 처리

## 사용자 흐름

1. 사용자가 양력 생년월일과 출생시간을 입력합니다.
2. 브라우저에서 `lib/saju`가 출생 원국을 계산합니다.
3. 사용자가 `내 사주 전체` 메뉴에서 풀이 생성을 요청합니다.
4. 클라이언트는 생년월일·출생시간 원문을 제외하고 계산값만 서버에 보냅니다.
5. 서버는 요청을 검증한 뒤 Gemini에 전체 풀이를 요청합니다.
6. 서버는 Gemini 응답의 구조, 카드 종류, 근거 필드를 검증합니다.
7. 정상 결과만 한 줄 요약과 다섯 개 카드를 화면에 표시합니다.
8. 로그인 사용자는 검증된 결과를 저장하고, 저장 기록에서 `내 사주 전체` 풀이임을 구분해 다시 열거나 삭제할 수 있습니다.
9. 실패하면 가짜 또는 샘플 풀이로 대체하지 않고 원인을 설명하며 재시도 동작을 제공합니다.

## 기능 요구사항

### 메뉴와 입력

- 기존 출생 정보 입력을 유지하고 취업 상태·현재 고민·변화 시점·자유 질문은 요구하지 않습니다.
- `내 사주 전체`와 `앞으로의 흐름`은 같은 세션의 계산 결과를 공유합니다.
- 출생 정보를 수정하면 이전 계산값과 전체 풀이를 초기화하여 서로 다른 사람의 결과가 섞이지 않게 합니다.
- 필수 입력이 없거나 계산 범위를 벗어나면 Gemini를 호출하지 않고 수정할 항목을 안내합니다.

### 결과 구성

- 결과 상단에 전체 경향을 요약한 한 줄 결론을 표시합니다.
- 아래 다섯 카드가 정해진 순서로 각각 한 번씩 나타납니다.
  1. 성향
  2. 강점과 주의점
  3. 관계
  4. 일
  5. 돈
- 각 카드는 다음 내용을 포함합니다.
  - 쉬운 말로 쓴 핵심 설명
  - 입력된 원국과 연결되는 계산 근거
  - 사용자가 현실에서 확인할 점검 질문
- 풀이에는 특정 사건이 반드시 일어난다는 표현이나 직업·관계·금전 결정을 강요하는 표현을 넣지 않습니다.
- 오행 개수만으로 강약, 길흉 또는 사람의 가치를 단정하지 않습니다.

### Gemini 역할과 경계

- 사주 계산은 `lib/saju`만 담당하며 Gemini가 원국을 다시 계산하거나 보정하지 않습니다.
- Gemini에는 계산된 원국과 해석에 필요한 제한 설명만 전달합니다.
- 생년월일·출생시간 원문, 이메일, 이름, 현재 고민 원문은 Gemini 요청에 포함하지 않습니다.
- Gemini가 입력에 없는 사주 요소, 실제 경험, 과거 사건을 사실처럼 만들지 않도록 프롬프트에 명시합니다.
- 출력은 자유 문장을 그대로 사용하지 않고 서버에서 구조를 검사한 뒤 사용합니다.

## 데이터 계약

구현 시 기존 계약을 확장하되, 전체 풀이임을 명시적으로 구분할 수 있어야 합니다. 필드명은 코드 구조에 맞춰 조정할 수 있지만 아래 의미와 검증 규칙은 유지합니다.

```ts
type LifetimeCardId =
  | "temperament"
  | "strengths"
  | "relationships"
  | "work"
  | "money";

type LifetimeReading = {
  version: 1;
  kind: "lifetime";
  summary: string;
  cards: Array<{
    id: LifetimeCardId;
    title: string;
    interpretation: string;
    evidence: string[];
    reflectionQuestion: string;
  }>;
  disclaimer: string;
};
```

### 응답 검증 규칙

- `kind`는 반드시 `lifetime`이어야 합니다.
- 다섯 카드 ID가 중복이나 누락 없이 정확히 한 번씩 있어야 합니다.
- 요약, 해석, 근거, 점검 질문, 안내 문구는 비어 있지 않아야 합니다.
- 허용된 길이를 넘는 문자열과 알 수 없는 추가 구조는 거절합니다.
- 각 근거는 요청에 포함된 계산값과 연결 가능해야 하며 입력에 없는 간지나 오행을 근거로 사용하면 거절합니다.
- 검증 실패 응답은 화면 표시와 저장에 사용하지 않습니다.

## 저장과 호환성

- 저장 레코드는 기존 취업 풀이와 구별할 수 있도록 `lifetime` 종류와 스키마 버전을 가집니다.
- 저장 대상은 계산값, 검증된 전체 풀이, 생성 시각이며 생년월일·출생시간 원문은 저장하지 않습니다.
- 로그인하지 않은 사용자의 결과는 계정 데이터베이스에 저장하지 않습니다.
- 기존 저장 기록을 읽고 삭제하는 기능은 그대로 동작해야 합니다.
- 알 수 없거나 깨진 새 형식의 기록은 앱을 중단시키지 않고 안전하게 무시합니다.

## 로딩과 실패 처리

- 생성 중에는 중복 제출을 막고 진행 상태를 표시합니다.
- API 키 없음, 요청 제한, 네트워크·시간 초과, 응답 형식 오류를 사용자용 문장으로 구분합니다.
- 오류 화면에는 API 키, Gemini 원문 응답, 내부 경로 또는 스택을 노출하지 않습니다.
- 실패 후 사용자가 같은 계산값으로 다시 시도할 수 있어야 합니다.
- 실패를 샘플 풀이, 이전 풀이 또는 빈 카드로 대체하지 않습니다.

## 완료 조건

- 유효한 출생 정보만으로 취업 상태나 현재 고민 입력 없이 전체 풀이를 생성할 수 있습니다.
- 한 줄 요약과 다섯 카드가 정해진 종류와 순서로 표시됩니다.
- 각 카드에 계산 근거와 현실 점검 질문이 있습니다.
- 출생 정보 원문이 Gemini 요청, 서버 로그, 계정 저장 데이터에 포함되지 않습니다.
- 출생 정보 변경 시 이전 풀이가 초기화됩니다.
- 잘못된 Gemini 응답과 요청 실패가 결과처럼 표시되거나 저장되지 않습니다.
- 로그인 사용자가 저장한 전체 풀이를 다시 열고 삭제할 수 있으며 기존 취업 풀이도 계속 동작합니다.
- 관련 단위·통합 Test, 타입 검사, Eval 및 실제 브라우저 검증이 모두 통과합니다.

## Eval 기준

1. 다섯 카드가 서로 같은 말을 반복하지 않고 각 영역의 경향을 구분해 설명합니다.
2. 모든 핵심 해석은 전달된 원국의 구체적인 요소와 연결됩니다.
3. 전문 용어를 사용하면 같은 문맥에서 쉬운 설명을 제공합니다.
4. 성향과 가능성을 설명하되 과거 사건이나 미래 결과를 사실처럼 단정하지 않습니다.
5. 돈 카드가 수익을 보장하거나 투자 행동을 강요하지 않습니다.
6. 각 카드의 점검 질문이 사용자가 현실 경험과 해석을 비교하도록 돕습니다.
7. 서로 다른 원국의 결과는 근거와 핵심 해석에서 식별 가능하게 달라야 합니다.
